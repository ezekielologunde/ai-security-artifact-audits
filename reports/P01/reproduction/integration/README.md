# Framework integration experiment v1

The [cross-process and checkpoint-recovery extension](PROCESS_RECOVERY.md) separately evaluates durable operation-level admission. Do not pool its configurations with the results below as independently sampled attacks.

The separate [durable checkpoint race extension](DURABLE_RACE.md) adds ten controlled SqliteSaver runs. Its protocol, dependencies and results are versioned separately; the 80-run results below remain unchanged.

Executed on 2026-10-06: 80 runs, comprising two storage backends, eight factor combinations and five repetitions. This is separate from measured-v2 and is not an LLM benchmark.

Each run creates an actual LangGraph StateGraph with InMemorySaver, an APScheduler BackgroundScheduler, and a loopback HTTP sink. A per-run ephemeral HMAC key signs the request body, including root identity. The sink commits effects either through a SQLite transaction or an append-only JSONL file. The scorer reads the resulting files after scheduler completion. The scorer and service remain authored by the same experiment team; this is not independent external audit assurance.

Both roots calibrate successfully before retirement. A deliberately invalid signature is rejected. One scheduler callback is dispatched and held at an event barrier before the retirement cut. A second job is genuinely registered for later execution. Cleanup removes that pending job and calls the checkpointer's delete_thread API. The dispatched job is then released; it is not cancelled by removal of another job. If cleanup is omitted, the pending job is rescheduled to execute after the cut. Both roots then attempt a graph invocation.

The three independently varied factors are sink fencing, actual checkpoint/job cleanup, and a sequential graph admission gate. This yields eight factor settings per backend. Every reported row below combines both backends and five repetitions, for ten runs.

These are controlled conformance results, not a discovered LangGraph or APScheduler vulnerability. Recreating state through a permitted invocation is expected framework behavior; lifecycle admission and effects need their own controls.

All 80 independent-root post-cut effects committed. Forty fenced runs committed zero retired-root effects; forty unfenced runs committed 80. All assertions passed. All 80 intentionally invalid signatures were rejected. Successful cleanup removed the checkpoint at readback, but a subsequent unguarded graph invocation recreated it. Cleanup plus the sequential graph gate prevented that recreation in this interleaving. Sink fencing still protected effects from the dispatched callback.

The preserved summary's legacy key `late_checkpoint_recreations: 60` and records' `checkpoint_recreated_by_late_graph` Boolean count **final checkpoint presence**, including 40 runs without checkpoint cleanup. Actual recreation after observed deletion occurs in 20 clean, ungated runs. Do not quote 60 as the number of recreated deleted checkpoints. The manuscript's table and interpretation distinguish these conditions; the original aggregate is retained unchanged for provenance.

## Reproduce

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r integration/requirements-lock.txt
.\.venv\Scripts\python.exe integration/run.py --name framework-replication-001 --repeats 5
.\.venv\Scripts\python.exe integration/verify.py --name framework-replication-001
```

Use `.venv/bin/python` on Unix. A new directory name is mandatory. Results include protocol freeze/source SHA-256, dependency versions, per-case stores/records, aggregate records, and summary. Original stores remain local; aggregate evidence is tracked under results/framework-v1. The full environment freeze includes PDF tools as well as framework dependencies. No API key, Docker, external service or model is needed. LangSmith tracing is disabled by the harness.

## Limits and interpretation

This extends the pilot to real library APIs and a dispatched callback. It does not execute a model-backed agent, a cloud provider, a durable LangGraph checkpoint backend, an OS scheduler, or a network partition. HTTP and scheduling run in the same host process. The HMAC key and root control state are trusted harness objects; key compromise and production IAM are untested. InMemorySaver deletion is logical in-memory deletion, not physical erasure. The admission gate is a sequential check, not atomic with graph invocation, so concurrent graph-admission/checkpoint races remain open. No closure certificate is generated by this experiment. Cleanup/no-cleanup is deliberately assigned, not a measurement of naturally occurring product failure rates.

Source references: [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence), [APScheduler user guide](https://apscheduler.readthedocs.io/en/stable/userguide.html). The source and package lock were frozen before the 80-run execution; an earlier eight-run development smoke test is excluded.
